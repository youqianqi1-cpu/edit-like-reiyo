# 剪出帧我 · Edit like Reiyo

像 Reiyo 一样，剪出有活人感的 IP 视频。

把自由剪辑师 Reiyo 的剪辑判断交给 Codex：选完整的一遍，精细收紧气口，让字幕、大字、景别、素材和声音跟着表达发生，同时保留你自己的语气和偏好。也可以只让它看片，给出文案、拍摄和剪辑建议。

免费试用，适合已经在使用 Codex、电脑上装有剪映专业版的真人口播创作者。

**v0.1.4 加入剪辑前的素材帧率与原声音量检查，保留 v0.1.3 的声音读取修复。已认可的气口、字幕和声音选择规则保持不变。**

新草稿会根据实际选用的主素材确定帧率；检查原始左右声道的音量大小、逐秒变化和异常线索，不自动把所有声音放大。已有草稿、已确认剪口、字幕和用户自行修改的音量保持原样。

已在 M 系列 Mac、剪映专业版 11.6.0 新建 15 秒测试草稿：原片为 24 帧，剪映实际显示 24.00 帧/秒，保存重开后保持一致；正常播放时左右声道音量表有变化，原声增益仍为 0.0 dB。发布包还完成了 10 分 11 秒原片的声音读取、音量统计与逐字识别。程序检查 15 项通过，3 项便携媒体依赖测试跳过；Windows 真机仍待验证。本次验证不等同于全片听感验收，也没有改动原有草稿。

已安装的用户，把这句话交给 Codex：

> 请按本页安装说明更新「剪出帧我」到 v0.1.4，保留我的自定义内容和已有草稿。以后剪辑前先检查原片帧率和原声音量，新草稿跟随主素材帧率；已确认的剪口、字幕和我改过的内容不要动。

38 项剪映收藏音效检索目录、两款字体以及原有声音读取修复继续保留。本次没有加入新的网感包装规则。

## 第一次：把这句话发给 Codex

```text
帮我安装「剪出帧我」这个 Skill：https://github.com/youqianqi1-cpu/edit-like-reiyo
请读取页面下方的“给 Codex 的安装说明”，替我完成下载、安装和检查。
```

让 Codex 把 Skill 装好，不用自己建文件夹或复制剪辑规则。安装完成后，在下一轮消息里开始使用；如果当前客户端还没显示它，开一个新聊天。

已安装旧版的人，把“安装”改成“更新”，并补一句“保留我的自定义内容”。

## 以后：给它视频，再说一句

```text
用「剪出帧我」剪这条视频，新建草稿，原来的别动。
```

视频放在当前任务能访问的文件夹里，告诉它文件位置就行。已有字幕偏好、想保留的句子，也可以像平时聊天一样补充。

第一次剪辑会检查电脑条件；缺少配套工具时由 Codex 说明并协助准备。Windows 先试一小段，确认新草稿能正常打开播放后再继续全片。**安装完成与这台电脑已经能完成剪辑，是两件事。**

## 一直闪烁“等待回答／等待批准”，却没有按钮怎么办？

如果页面没有显示具体问题或批准按钮，不用一直等，也不要反复发送“同意”“继续”。页面显示的总用时不能直接当成实际剪辑耗时。

1. 先切到其他聊天再回来，查看聊天底部是否出现具体问题或批准按钮。有的话，读清楚对应操作后再决定。
2. 仍然没有时，停止这轮任务。等其他任务停妥后，彻底退出 Codex，再打开原来的聊天。保留已有进度，不用重装 Skill，也不用从头重剪。
3. 重开后仍然闪烁，就新建一个排查用的聊天，复制下面这段，把任务名称换成自己的。

```text
请排查任务「这里填卡住的任务名称」为什么一直闪烁“等待回答”或“等待批准”，却没有显示问题或批准按钮。

只检查，不执行剪辑、不重新安装 Skill、不修改设置或任何草稿。

请找到这条任务最近的聊天记录和应用运行记录，核对：
1. 最后一个完成的操作是什么？
2. 随后是否真的发出了提问或批准请求？如果有，原文是什么、对应什么操作？
3. 是否有子任务还在等待回答？
4. 是否出现连接中断、请求失败，或任务已经结束但页面仍显示等待的情况？

Mac 的应用记录通常在 ~/Library/Logs/com.openai.codex/，聊天记录通常在 ~/.codex/sessions/；设置过 CODEX_HOME 时，聊天记录在该目录的 sessions 文件夹里。其他系统请查当前应用实际使用的记录位置，不要照抄 Mac 路径。如果没有访问权限，请说明具体缺少什么。

最后用普通中文告诉我：卡在哪一步、依据是哪几条记录、下一步怎么恢复。找不到证据就明确说尚未查明，不要猜。只摘取相关错误和请求，隐藏私人信息，不要上传整份记录。
```

把排查结果、Codex 版本号和问题截图发给 Reiyo 即可，截图里遮住私人信息。如果新聊天也不能正常回答，先停止试剪；可在聊天输入框输入 `/`，找到反馈入口，描述“等待回答闪烁但没有问题或批准按钮”，自行决定是否附带该聊天。

这是排查办法，不代表已确认故障原因，也不需要关闭安全检查或批准所有操作。记录位置与反馈方法参考 [OpenAI 官方排障说明](https://learn.chatgpt.com/docs/reference/troubleshooting#feedback-and-logs)。
