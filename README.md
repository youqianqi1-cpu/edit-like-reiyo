# 剪出帧我 · Edit like Reiyo

像 Reiyo 一样，剪出有活人感的 IP 视频。

把自由剪辑师 Reiyo 的剪辑判断交给 Codex：选完整的一遍，精细收紧气口，让字幕、大字、景别、素材和声音跟着表达发生，同时保留你自己的语气和偏好。也可以先只做选段和气口，再继续包装。

免费试用，适合已经在使用 Codex、电脑上装有剪映专业版的真人口播创作者。

**v0.1.11 试用版：补充剪映实际版本检查，以及首次使用、升级或重装后的短段验证。已认可的气口、字幕、大字、景别和音效规则保持不变。**

v0.1.10 加入的 Reiyo 逐条讲解的 86 条音效用法继续保留。

收藏索引保留193项，每条已讲解的声音保留适用语境、长短、语气、音量及句首句尾的区别。“可爱”也包括轻松的小得意。每讲三句寻找合适的落点，连续四句至少一处音效，按完整的话算，不按字幕条数或秒数补声。同一音效尽量不出现三次；默认正常音量，逐条另有要求时遵循该条。

已认可的气口、普通字幕、单层黄色大字与自身深蓝阴影、整句保持的景别及原生扩音器继续保留。新增只替换音效的随包工具，重做音效时保留画面、剪口、字幕、大字、景别、音乐及扩音器。原片与单条视频的选段、剪点、制作清单不随包发布。

v0.1.10 验证时在作者的剪映收藏取得候选，为约3分14秒的新试剪稿放置27处音效，按44句完整讲话检查覆盖；保存重开后核对其他剪辑保持原样，Reiyo 听看后认可。164项程序检查中161项通过、3项可选工具检查跳过。原有气口、字幕、大字与扩音器曾通过全新任务独立试剪；本轮音效没有另做陌生剪映账号取音验证。声音文件从使用者自己的剪映公共库按名称查找，不附作者收藏的声音文件。

需要分步看片时，可以说“先只剪气口”“只做气口加普通字幕”或“只做气口、字幕和大字”。后续修改保留已认可的剪口和个人修改；MG 动画由你另行提出。Windows 真机及各台学生电脑仍先做各自的短段验证。

已安装的用户，把这句话交给 Codex：

安装或更新的版本以仓库当前 [VERSION](https://raw.githubusercontent.com/youqianqi1-cpu/edit-like-reiyo/main/VERSION) 为准，下载入口见当前 [README 原文件](https://raw.githubusercontent.com/youqianqi1-cpu/edit-like-reiyo/main/README.md)。

## 第一次：把这句话发给 Codex

```text
帮我安装「剪出帧我」这个 Skill：https://github.com/youqianqi1-cpu/edit-like-reiyo
先直接读取仓库 main 分支当前的 VERSION 和 README.md，按最新说明下载、安装并核对版本，不使用搜索结果里的旧版安装包。
```

让 Codex 把 Skill 装好，不用自己建文件夹或复制剪辑规则。安装完成后，在下一轮消息里开始使用；如果当前客户端还没显示它，重启 Codex 后再开一个新聊天。

已安装旧版的人，把“安装”改成“更新”，并补一句“保留我的自定义内容”。

## 以后：给它视频，再说一句

```text
用「剪出帧我」剪这条视频，新建草稿，原来的别动。
```

只想先剪气口时，说“先只做选段和剪气口，保持原速和原音量，保存新草稿给我听”。

视频放在当前任务能访问的文件夹里，告诉它文件位置就行。已有字幕偏好、想保留的句子，也可以像平时聊天一样补充。

第一次剪辑会检查电脑条件；缺少配套工具时由 Codex 说明并协助准备。Windows 先试一小段，确认新草稿能正常打开播放后再继续全片。**安装完成与这台电脑已经能完成剪辑，是两件事。**

## 首次使用、剪映升级或重装后，先做短段验证

先让 Codex 检查实际安装的剪映版本和构建号，再用约6秒原片新建独立测试草稿：放入视频、可编辑文字及一处景别变化，保存重开播放；在剪映里改字保存后，再确认 Codex 能读到修改。通过后再剪整片，原稿保留。同一环境已经验证通过的记录可以复用。

2026年10月22日，本机 Mac 的剪映版本与构建号均为11.6.0，上述6秒测试通过。同日本机进入11.7测试系列后曾出现明确拒绝读取，重装11.6.0后恢复。该结果不代表所有同版本安装包、复杂效果、完整听感或Windows均已验证；以各台电脑的短段结果为准。

如果出现拒绝读取，Codex会停下并说明版本与具体卡点，不反复重试，不自动重新安装或更换剪映。你决定调整软件后，再做一次短段验证。

## 一直闪烁“等待回答／等待批准”，却没有按钮怎么办？

如果页面没有显示具体问题或批准按钮，不用一直等，也不要反复发送“同意”“继续”。页面显示的总用时不能直接当成实际剪辑耗时。

1. 先切到其他聊天再回来，查看聊天底部是否出现具体问题或批准按钮。有的话，读清楚对应操作后再决定。
2. 仍然没有时，停止这轮任务。等其他任务停妥后，彻底退出 Codex，再打开原来的聊天。保留已有进度，不用重装 Skill，也不用从头重剪。
3. 重开后仍然闪烁，就新建一个排查用的聊天，复制下面这段，把任务名称换成自己的。

```text
请排查任务「这里填卡住的任务名称」为什么一直闪烁“等待回答”或“等待批准”，却没有显示问题或批准按钮。

只检查，不执行剪辑、不重新安装 Skill、不修改设置或任何草稿。

请找到这条任务最近的聊天记录和应用运行记录，核对：
1. 最后一个完成的操作是什么？
2. 随后是否真的发出了提问或批准请求？如果有，原文是什么、对应什么操作？
3. 是否有子任务还在等待回答？
4. 是否出现连接中断、请求失败，或任务已经结束但页面仍显示等待的情况？

Mac 的应用记录通常在 ~/Library/Logs/com.openai.codex/，聊天记录通常在 ~/.codex/sessions/；设置过 CODEX_HOME 时，聊天记录在该目录的 sessions 文件夹里。其他系统请查当前应用实际使用的记录位置，不要照抄 Mac 路径。如果没有访问权限，请说明具体缺少什么。

最后用普通中文告诉我：卡在哪一步、依据是哪几条记录、下一步怎么恢复。找不到证据就明确说尚未查明，不要猜。只摘取相关错误和请求，隐藏私人信息，不要上传整份记录。
```

把排查结果、Codex 版本号和问题截图发给 Reiyo 即可，截图里遮住私人信息。如果新聊天也不能正常回答，先停止试剪；可在聊天输入框输入 `/`，找到反馈入口，描述“等待回答闪烁但没有问题或批准按钮”，自行决定是否附带该聊天。

这是排查办法，不代表已确认故障原因，也不需要关闭安全检查或批准所有操作。记录位置与反馈方法参考 [OpenAI 官方排障说明](https://learn.chatgpt.com/docs/reference/troubleshooting#feedback-and-logs)。
